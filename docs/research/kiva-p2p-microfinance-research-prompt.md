## このファイルについて

知人からのメールで「KIVA（国際的な P2P マイクロファイナンス組織）が『寄付』ではなく『融資』という手法を採っている点に注目し、国内で類似団体を設立しようと行動したことがある。その視点・視座はどうか」という示唆をもらった。
ハッカソンには落選したため、純粋な興味として「内容の理解」と「個人開発・小規模開発のネタになるか」を調べるためのプロンプト集である。

- 想定する使い方: 深いリサーチができる AI（Deep Research 系、Web 検索付きのチャット、Claude Code の調査モードなど）に、下記「メインプロンプト」をそのまま貼り付ける。
- 結果を読んだあと、「フォローアッププロンプト」で深掘りする。
- 出力は日本語。調査日を明記させる（規制や KIVA の API 事情は変わりやすい）。

```text
# 背景
知人から次の示唆を受けました。
「KIVA という国際的な P2P マイクロファイナンス組織を知っているか。この組織の手法が『寄付』ではなく『融資』である点に注目し、
日本国内で類似団体を設立しようと動いたことがある。そうした視点・視座を AI 関連のアイデアに活かしてはどうか。」

私はソフトウェアエンジニア（主に TypeScript）で、ハッカソン向けに検討していましたが落選したため、

商用の金融サービスを本当に立ち上げる予定は今のところありません。

# 調査してほしいこと

## 1. KIVA そのものの理解
1-1. 組織概要: 設立経緯、法人形態（NPO）、本拠地、規模（累計融資額、貸し手数、借り手数、対象国数）、直近の年次報告書の数値。
1-2. 仕組み: 貸し手（Lender）→ KIVA → フィールドパートナー（現地 MFI）→ 借り手、という資金フロー。
     貸し手の利息が 0% である理由、フィールドパートナーが借り手に課す金利の実態、返済率、デフォルト時の扱い、為替リスクの負担者。
1-3. 「寄付ではなく融資」であることの設計上の意味: 資金が循環する（再融資できる）、借り手の尊厳、貸し手のエンゲージメント、
     返済というフィードバックループ。これを支持する研究・批判する研究の双方を挙げる。
1-4. 有名な批判と KIVA の対応: 2009 年の「KIVA は本当に P2P か（資金は事前に融資されている）」論争、
     フィールドパートナーの高金利問題、インパクト評価の限界。
1-5. 技術面: KIVA が公開している（いた）API・データセット（過去の REST API の廃止状況、現在の GraphQL API の有無と利用条件、
     データスナップショットの公開状況、ライセンス）。Kiva Protocol（デジタル ID・信用履歴の試み）の経緯と現状。
1-6. ボランティア運用: 翻訳・編集・レビューなどを人力ボランティアで回している部分（AI 代替の候補になりうる箇所）。

## 2. 類似モデルと「融資 vs 寄付」の比較
2-1. 海外の類似・派生モデル: Zidisha（仲介なし直接 P2P）、Lendwithcare、Babyloan、Kiva U.S.（米国内直接融資）、
     Grameen 系、信用組合型。それぞれ KIVA との違いと、うまくいった点・行き詰まった点。
2-2. 行動経済学・開発経済学の知見: 融資型と寄付型で、資金提供者の継続率・金額・満足度・インパクトはどう違うか。
     マイクロファイナンスの効果に関する RCT（ランダム化比較試験）の主要結論（効果は限定的、という議論を含む）。
2-3. 「返済される前提のお金」と「返ってこない前提のお金」で、ソフトウェアの設計（UX、通知、信用、コミュニティ機能）は何が変わるか。

## 3. 日本で類似団体・サービスを作る場合の壁
3-1. 法規制の整理: 貸金業法（貸金業登録の要否）、出資法（金利上限・預り金規制）、資金決済法（資金移動業・前払式支払手段）、
     金融商品取引法（第二種金融商品取引業、匿名組合型ソーシャルレンディング）、利息制限法。
     「個人が個人に貸すこと」「団体が無利子で貸すこと」「貸し手から資金を集めて貸し付けること」のそれぞれがどの法律に触れるか。
3-2. 国内の先行事例: ソーシャルレンディング（maneo 等の問題事例と 2019 年前後の規制対応・借り手情報開示の解禁）、
     NPO バンク（未来バンク事業組合、コミュニティ・ユース・バンク momo 等）、グラミン日本、
     生活福祉資金貸付制度、信用金庫・労働金庫、寄付型・購入型クラウドファンディング（READYFOR、CAMPFIRE 等）。
     「国内で KIVA 型を目指した試み」が存在すれば、その顛末。
3-3. 文化・市場要因: 借金への忌避感、既存の公的融資制度の充実度、低金利環境、信用情報インフラ、
     「国内の誰に貸すのか（資金ニーズがどこにあるのか）」という需要側の問題。
3-4. 規制に触れずに「融資的な体験」を作る抜け道の有無: ポイント・疑似通貨、時間（スキル）の貸し借り、
     寄付＋返礼報告、海外 KIVA への導線をつくるだけ、など。それぞれの法的リスクと面白さ。

## 4. AI を絡める余地
4-1. KIVA や MFI の業務の中で AI が効きそうな箇所を列挙し、それぞれ「技術的な難しさ」「データの入手可能性」「倫理・規制リスク」で評価する。
     例: 代替データによる信用スコアリング、借り手ストーリーの翻訳・要約・生成、不正検知、貸し手とのマッチング・推薦、
     返済予測、フィールドパートナーのデューデリジェンス、インパクト計測、借り手向けチャットボット、AI エージェントによる自動貸付判断。
4-2. 信用スコアリングへの AI 利用に関する規制動向: EU AI Act でのハイリスク分類、日本の AI 事業者ガイドライン、
     金融庁の AI 利用に関する考え方、バイアスと説明責任の問題。
4-3. 既に AI を使っている金融包摂系の事例（Tala、Branch、M-Pesa 周辺、国内のオルタナティブ信用スコアなど）と、その評判。

## 5. 個人開発・小規模開発の題材としての評価
5-1. 「お金を実際に動かさない」前提で作れるものを 3〜5 案出す。各案について、
     コンセプト、コア機能、使えるデータ（KIVA 公開データ等）、技術スタック案（TypeScript / Node.js 前提）、
     1〜2 週間で MVP になるか、デモ映えするか、学びの大きさ、法的リスク、を 5 段階で評価する。
5-2. 「お金を動かす」前提にした場合に追加で必要になる手続き・コスト・パートナーをざっくり見積もる。
5-3. 似たことをやっているオープンソースプロジェクトや過去のハッカソン作品があれば挙げる。

# 出力形式

- 最後に「未解決の問い」を 5 個以上列挙する。
```

## 調査のあとで自分が判断したいこと（メモ）

- 「寄付ではなく融資」という視座は、金融のプロダクトではなく「返済・循環・信頼のループを持つソフトウェア」一般に転用できるか。
- 本当にお金を扱わなくても、KIVA 的な面白さ（自分の 25 ドルが誰かの商売になって返ってくる）を再現できるか。
- AI は「翻訳・要約・審査補助」といった地味な部分で効くのか、それとも新しい体験を作れるのか。
- ハッカソン向けではなくなった今、学習目的として最も費用対効果が高い切り口はどれか。
